# 周奥口味规则（personal profile 的校准依据）

> 这份文档是 `personal` profile 与 `rewrite` 模块的规则来源。
> 语料来自本人私库（AI 会话事件流），**原文不入库**；本文只出现合成样例，
> 证据以事件 id + 统计量形式引用（id 是 12 位不透明哈希，可回源核对、不泄内容）。
> 提取脚本：`tools/extract_private_corpus.py`，产出全在 `corpus_private/`（gitignore）。

## 0. 为什么需要这一层

三个公开 profile（academic / general / official）校准的是"中文 AI 味"的通用特征。
但**本人对文案的取舍有明确且可量化的偏好**，公开语料测不出来——比如"关怀腔"
在通用语料里是中性甚至加分的，在本人这里是被毙的第一名。这一层把私人标注数据
吃进规则库，用于审自己的产品文案（eggpaper / human-vs-ai 这类界面文案与梗）。

**定位**：`personal` 是**短文案审查器**（界面文案、提示语、标题、自媒体短句），
不是通用散文检测器。长文请用 academic / general / official。

## 2. 口味条目（T 编号，personal profile 引用）

每条给出：判别式 / 证据 / 合成示例。合成示例是照着模式自造的同类句，
用于测试与文档演示，**不是语料原文**。

### T1 劝慰腔 —— 被毙率最高的一类

- **判别式**：`[，,].{0,14}(跑不了|还在原地|不丢人|不算熬夜|是正常|别硬撑|又不会跑)`
- **证据**：首轮 15 条被毙稿中 3 条（`2bba79e82622`）；定稿 37 条中 0 条（0%）
- **为什么**：劝慰句的结构是「陈述状况 + 给对方一个台阶」，它替读者完成了情绪
  管理。读者没有得到信息，只收到了安慰——这就是"暖心的 AI 味"。
- **合成示例**：`别急，代码明天还在仓库里。`（同类结构，非原文）
- **处理**：删。真要安慰，用一个梗或者干脆不说。

### T2 抒情升华

- **判别式**：`[，,](就是|才是|是)(最好的|你的|一场|偷来的)` 或含 `陪你`
- **证据**：首轮 15 条中 2 条、次轮 16 条中 2 条；定稿 0 条（0%）
- **为什么**：把日常动作升格成有意义的意象（把开灯、翻页这类动作说成"你的主场"
  之类）。升华不增加信息，只增加修辞密度。
- **合成示例**：`窗口一开，就是你的战场。`
- **处理**：删升华半句，留动作。

### T3 说理解释腔

- **判别式**：`不是.{0,8}(问题|错|摆烂|态度|罪|偷懒)` 或 `(是科学|是生理学|不心虚)`
- **证据**：首轮 15 条中 3 条；定稿 0 条（0%）
- **为什么**：给一个不需要辩护的行为做辩护（"休息不是摸鱼，是科学"这种句式）。
  产品文案里的辩护句通常在解释"我为什么这么设计"，属于 T11 的近亲。
- **合成示例**：`摸鱼不是偷懒，是给大脑做碎片整理。`
- **处理**：删。

### T4 效率承诺

- **判别式**：`(效率|翻倍|事半功倍)`
- **证据**：首轮 15 条中 1 条（事件 `2bba79e82622`）；定稿 0 条
- **为什么**：给一个无法验证的收益承诺。与 T11 同源——都在"说明功能/效果"。
- **合成示例**：`早读十分钟，一天效率翻倍。`
- **处理**：删；确有收益就用具体数字和条件说。

### T5 劝诫长句

- **判别式**：`.{2,}[，,].{0,10}(早点睡|注意身体|照顾好身体)` 或 `(别|不要)(熬太晚|熬夜).{0,12}[，,].{1,20}`
- **证据**：首轮 15 条中 2 条；定稿 37 条中存活 1 条——存活的是**一句话短问候**，
  被毙的全是"铺垫 + 祈使 + 理由"的长句（判别在结构不在题材）
- **合成示例**：`夜深了，字也看不清了，早点睡。`
- **处理**：删或压到最短。

### T6 夸张赞美

- **判别式**：`(太阳还没|比月亮|最努力|最棒)`
- **证据**：首轮 15 条中 2 条；定稿 0 条
- **为什么**：把读者往高处架。本人的口味是**吐槽/自嘲**，不是捧。
- **合成示例**：`月亮都下班了，你还在。`
- **处理**：改成吐槽或自嘲。

### T7 「X 的你」句式

- **判别式**：`^[^，]{0,8}的你[，,]`
- **证据**：首轮 15 条中 4 条命中此句式（事件 `2bba79e82622`）；定稿 0 条
- **为什么**：把读者推成第三人称观察对象，是抒情腔的句法载体。
- **合成示例**：`深夜的你，还在改这一版。`
- **处理**：改回第二人称直说，或改成具体动作。

### T8 宏大升格

- **判别式**：`(人类|世界|宇宙|所有人)的?(至暗|巅峰|终极|最高|最低)`
- **证据**：首轮 15 条中 1 条（事件 `2bba79e82622`）
- **合成示例**：`周一上午，打工人的至暗时刻。`
- **处理**：降级到具体名词。

### T9 揭短说教

- **判别式**：`——\s*你.{0,4}(也|又|总是|还是)`
- **证据**：首轮 15 条中 1 条（事件 `2bba79e82622`）。注意同结构但主体不同的
  句子在定稿里存活了——把用户的**话**当梗复述 vs 直接揭用户的**短**，差别在主体。
- **合成示例**：`说好只改一行——你上次也是这么说的。`
- **处理**：删；要玩这个梗，把矛头指向自己。

### T10 空泛鼓励

- **判别式**：`(好好读|加油|稳住|你可以的)`
- **证据**：首轮 15 条中 1 条；定稿 0 条
- **合成示例**：`继续加油，你可以的。`
- **处理**：删。鼓励必须有具体对象才有信息量。

### T11 功能说明腔 —— 处理方式是整句删，不是改写

- **判别式**：`(自动[挑选]|先.{1,4}再|一次最多|请直接|点击|拖[入拽]|勾选|支持)`
- **证据**：事件 `79085432a6b4` 一次性点名了三条此类文案（说明"怎么挑内容"
  "怎么生成回答""一次能用多少"），要求"不要有无用文案"；`e9c030c5a88e`、
  `117cbc53559c`、`63cbaaa6f270`、`fe6c60314e3a` 各有一处整句删除的实例；
  `2c822c5e3b78` 删掉了一个功能名标题，并把一条拖拽说明压成最短指令。
- **为什么**：解释「产品怎么工作」的文案，用户用一次就懂；写出来只是噪声。
  本人的处理一律是**整句删**——不是压缩、不是换说法。
- **合成示例**：`自动匹配相关段落，一次最多三条。`（这是照句式自造的演示句）
- **处理**：**整句删**（R2）。唯一例外是操作确实非直觉时，压成最短的操作指令
  （`2c822c5e3b78` 那条是压短而不是删）。

### T12 收束保险腔

- **判别式**：`(综上所述|总而言之|总之|总的来说|由此可见|不得不说)`
- **证据**：本人真人基线 0.01 次/千字，AI 产线 0.05 次/千字（差 10 倍，见 §3）
- **处理**：删。

## 3. 风格指纹量化（H5）

同一作者、同一批任务下的两条流：本人输入 vs AI 产出。（每千字次数）

| 标记 | 我 | AI 产线 | 倍数 | 说明 |
|---|---|---|---|---|
| 破折号 `—` | 0.99 | 6.91 | **0.14×** | 最锋利的判别项：我几乎不用破折号 |
| 收束词（综上/总之） | 0.01 | 0.05 | **0.10×** | 我不用总结腔收尾 |
| 「不是 A 而是 B」 | 0.03 | 0.13 | **0.19×** | 否定式排比 |
| 顿号三连（A、B、C） | 0.30 | 1.30 | **0.23×** | 排比堆砌 |
| 感叹号 | 0.06 | 0.31 | 0.19× | |
| 问号 | 0.16 | 0.45 | 0.36× | AI 爱用问句拉互动 |
| 冒号 | 7.29 | 9.73 | 0.75× | 差距最小的一个 |
| 引号 | 8.18 | 18.80 | 0.44× | |

文案池层面的对照更极端：

| 特征 | 被毙 31 条 | 定稿 37 条 |
|---|---|---|
| 劝慰 / 抒情 / 说理 / 效率 / 夸张 / 「X的你」/ 空泛鼓励 | 55%（合计） | **0%** |
| 具体名词（DDL、组会、参考文献、文献、paper、accept…） | 19% | **60%** |
| 网络梗 / 口语 | 16% | **40%** |

**结论**：我的文案偏好是「具体名词 + 梗/口语」，排斥「劝慰/抒情/说理/升华」。
这不是"短就好"——被毙稿平均 12.4 字，定稿 13.2 字，长度几乎一样。
**差别在句子的功能**：定稿在吐槽或自嘲，被毙稿在安慰或升华。

## 4. 改写准则（rewrite 模块的硬约束）

### R1（最高优先）删减哲学

> 不是一味的删减，而是该多说时多说，该少说时少说，重要数据和结论要保留。

—— 事件 `c1ac954fc613`（2026-08-22），同一准则的另一处表述在
`d3ea83a41478` / `f1395277c79c`（"哪里该增哪里该删要搞清楚，而不是一味地增加"）。

**工程含义**：改写器必须输出三档（删 / 改 / **保留**），且"保留"档的第一判据是
**含数字、结论、事实断言**的句子——这类句子在任何腔调下都不许动结构。

### R2 功能说明整句删

T11 命中且不是操作指令 → 删，不压缩、不改写。

### R3 具体名词替换泛化表达（提示，不作判据）

把"这套机制""相关工作""效率"这类泛称换成领域实物名（DDL、组会、参考文献、
accept、数据）。定稿里具体名词占比 60%，是被毙稿的 3 倍。

**注意**：这一条只作为改写方向提示，不单独构成"该改"的判定。首轮实现把它
当判据用，自检时 47/53 条正常界面文案（功能标签、CLI help、参数说明）被判
"该改"——缺名词是"没加分"，不是"有毛病"。这与本项目"弱信号不单独定罪"
的原则一致，已固化为回归测试。

### R4 允许网络梗，不用过气梗

梗要贴当前语境（科研/文献/DDL 场景），且优先自嘲而非捧读者。
保留 `连滚带爬`、`牛马`、`摸鱼`、`不吱声` 这类仍活跃的表达；
避免使用已经烂大街到失去趣味的梗。

### R5 长度不是目标

改写后可以更长（8 组亲改里 5 组变长或持平）。目标是句子的**功能**从
"安慰/升华"转成"吐槽/自嘲/具体"。

## 5. 工程落地

| 产物 | 说明 |
|---|---|
| `human_vs_ai/rules/personal.yaml` | T1–T12 落成规则，`taste:` 字段标注口味条目编号 |
| `human_vs_ai/rewrite.py` | 逐句给出 删/改/保留 三档 + 改写候选（R1 优先） |
| `human-vs-ai rewrite <file>` | CLI 入口 |
| 网页版「改写建议」 | 与检测同一份规则，浏览器内跑 |
| `tools/eval_taste_regression.py` | 私库回归：被毙稿召回/定稿误报/改写维度三中其二 |
| `tools/check_private_leak.py` | 硬边界守护：入库文件里不许出现私库语料的 6 字级片段 |
| `tools/extract_private_corpus.py` | 语料提取（只读源目录，产出全在 corpus_private/） |

### 验收线（实测结果）

| 验收项 | 目标 | 实测 | 判定 |
|---|---|---|---|
| 被毙稿召回 | 100% | 31/31 = 100% | PASS |
| 定稿误报 | 无 high/medium | 0/37 · 我亲改 8 组 0 命中 | PASS |
| 改写产出物三中其二 | ≥80% | 5/6 = 83.3% | PASS |

复跑命令：`python tools/eval_taste_regression.py`（需 corpus_private/，缺失自动跳过）。

**已知边界（不粉饰）**：6 个改写对里只有 1 对（谐音梗那条）改写器判不出方向——
规则化改写做不出梗，那一条正是"梗要人补"的实例。另有一个诊断数字：
改写器对 AI 原句给出「删/改」判定的比例是 1/6，其余 5 条是"方向对但语感差
一口气"的半成品（含具体名词或梗、无腔调），规则判不出，只能人补。这条限制
写进模块输出本身，不让用户误以为它能替人写梗。

**自检**：用本规则审查本项目自己的界面文案（网页 placeholder/标签、CLI help、
扩展 package.json 描述、报告免责与统计行）。首轮命中 1 条——网页初始
空态的"粘贴文本后自动分析"，按 T11 整句改成"粘贴正文即出报告。"。
精简轮（v0.7.1）复查 130 条当前界面文案，真实命中 0（提取脚本误收的
正则模式串不计）。功能标签与 help 文本不应被判"该改"：R3（缺具体名词）
已因此从判据降为提示——自检首轮它把 47/53 条正常界面文案判成"该改"，
正是本项目的设计原则（弱信号不单独定罪）要避免的事。

## 6. 与公开 profile 的关系

- 公开三 profile 的规则**不动**：personal 是叠加层，不是替代。
- personal 复用同一套引擎、同一份报告格式、同一条免责（"风格提示，
  不是 AI 判定；单条命中不构成证据"）——这里命中的是"不像我"，
  更不是"AI 生成"。
- 语料与阈值全部来自私人标注；公开仓库里只有规则与合成样例。
