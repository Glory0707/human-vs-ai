# human-vs-ai 项目设计

> v0.5 · 2026-09-20。已实现能力见 [README](../README.md)，本文只保留定位、原则、取舍与未竟事项。

---

## 1. 一句话定位

**本地优先、可解释的中文 AI 味分析器：逐句指出哪里像模板、为什么像、怎么改——不判 AI 概率。**

四个差异点：

1. **可解释** —— 每处命中带规则名、语言学解释、修改方向、研究出处；商业工具给分数不给解释，我们反过来。
2. **过评测的规则** —— 每条规则带着 C-ReD/HC3 上的区分度数字；证伪即删，砍掉清单防复活。
3. **本地优先** —— 零网络调用，文本不上传；唯一硬依赖 PyYAML。
4. **按场景组织** —— 词表规则分 profile（学术/通用/公文…），统计底盘共用；实测证明跨文体复用词表必然失效。

## 2. 设计原则

1. **推断不是判定**：命中≠AI。报告措辞永远是风格提示；免责声明随每次输出走。
2. **弱规则必须共现**：`low` 级规则全文 ≥2 处命中才升为正式发现，孤立命中进参考区。
3. **规则必须过评测**：没有区分度数字的规则不进库；评测脚本（tools/evaluate_*.py）是规则库的看门人。
4. **可溯源**：每条规则给解释与出处（维基/humanizer/社科院/人大编码/实证论文），`explain` 命令可查全文。
5. **诚实报告口径**：统计指标样本不足（<3 句）不判；切分口径全文唯一（字级 2-gram，跨端可复现）——宁可不判，不给不可比的数字。
6. **界面减法**：同一句多规则命中聚合一节，不重复贴原句；删掉这行字用户没损失就删。
7. **做减法**：每轮规划先问"哪些该砍"。

## 3. 砍掉清单（防复活）

| 砍掉项 | 理由 | 实测依据 |
|---|---|---|
| AI 生成概率分数 / "能过知网"承诺 | 检测器不可靠是 OpenAI/斯坦福/法院/Nature 的共同结论；给分数等于自欺 | OpenAI 2023-07 下架 classifier；斯坦福 61% 误判；Newby v. Adelphi 判"devoid of reason" |
| S-TRIAD-01 三连排比（学术 profile） | 学术摘要是真人的方法条件列举 | C-ReD 区分度 -0.17（真人 54% vs AI 36%）；问答文体 +0.22 有效，留待 general |
| D-TTR-01 词汇丰富度（学术 profile） | 方向随文体反转，单一方向判定会误导 | C-ReD：AI 0.715 **>** 真人 0.649（真人摘要术语重复是精确性）；HC3：AI 0.610 **<** 人类 0.696 |
| L-SAFE-01 万金油对冲 | 零区分度 | C-ReD ±0.00 |
| D-NGRAM-01 4-gram 复现（official profile） | 公文本身就是套语复现文体，真人 0.24–0.59 与 AI 无区分度 | 首轮公文评测 100% 误报的主因之一 |
| 自动改写 | 改写是 humanizer 类 skill 的地盘；linter 管检测+解释，两者是上下游不是竞品 | — |
| 训练二分类检测模型 | 黑盒，撞车学术界，且 SHAP 研究证明事后归因不可靠 | 计算机应用与软件 2024：黑盒归因关键词多为数字/生僻字 |
| 在线服务 / API 优先 | 与本地可解释定位自相矛盾；隐私是刚需不是卖点 | — |
| 单一"AI 味总分" | 分数会滑向"AI 率"判决语义；报告分层呈现（逐句命中 + 统计指标）已经够用 | — |

## 4. 排队事项（按需启动）

- **P2**：general profile 当代语料校准（抓取路径评估见 plan.md M5：公开渠道反爬与条款风险高，优先本地生成+用户自愿提交的匿名样本）· 公文 AI 真实样本扩充（当前为构造样本，有自我偏差）· Obsidian 插件（engine.js 直接复用）
- **P3**：规则 era 自动化挖掘（从 C-ReD 各模型子集季度重挖词频漂移）· 句级困惑度（Qwen 本地小模型，可选插件不进默认依赖）· 观点反复解释检测（需语义相似度，n-gram 只能部分覆盖）· general profile 当代语料校准（互动尾巴/万能开场在 2023 语料测不到，待收集 2025-2026 自媒体语料）

## 5. 架构（已验证）

```
CLI（argparse，四个子命令：check / stats / explain / profiles）
        │
引擎 engine.analyze()
        │
   ┌────┴─────────┬──────────────┐
切分 segment   规则库 YAML      统计 stats
（MD 清洗/     （academic 17 条  （句长CV/MATTR/
 分段/分句）    + general 10 条   连接词密度/4gram）
               + official 8 条）
        │
报告 report（terminal ANSI / markdown / json，同一份内容三种出口）

网页版：web/index.html（单文件，engine.js 同构实现 + 规则 JSON 注入，
tools/build_web.py 构建，tools/check_web_consistency.py 守护两端一致）

VS Code 扩展：vscode-extension/（复用 engine.js/rewrite.js/render.js 与规则 JSON，
tools/build_vscode.py 注入；命令 analyze（分析报告）+ rewrite（改写建议）
各一个 Webview 面板，node smoke-test.js 冒烟 + 一致性测试守护）
```

工程纪律：零网络调用；切分口径全文唯一且跨端可复现（字级 2-gram，不依赖任何分词库，v0.11.0 起 jieba 退场）；规则阈值全部放 YAML 不进代码（校准只改数据）；报告渲染与引擎解耦（JSON 是唯一事实源，terminal/md 都是它的投影）；双实现不许独立演化（一致性测试是网页版的发布门）。

## 6. 验证基线（实测记录）

- **单元测试**：84 项（切分 9 / 统计 6 / 引擎 10 / 边界 9 / 报告与文案 7 / 端到端区分度 3 / 综合评分 6 / 口味与改写 34），`python -m pytest tests/ -q` 全绿；其中私库回归 5 项在无 corpus_private/ 时自动跳过
- **C-ReD paper 域首轮校准**（2026-09，真人 80 vs deepseek-v3/qwen-3/gpt-4o/deepseek-r1 各 80）：
  - 词表规则句均命中：真人 0.046 vs AI 0.170–0.307，AUROC **0.804**（删除反向规则前 0.626）
  - 句长 CV：真人 0.483 vs AI 0.274–0.383（四模型全部低于真人），AUROC **0.799**
  - deepseek-r1（推理模型）确认最难检：CV 0.383 最接近真人
- **HC3-Chinese 首轮校准**（2026-09，medicine+baike 各 120）：TTR AUROC 0.808、句长 CV 0.763（v0.8.0 切分修正后复评；首轮为 0.800/0.760），方向与 C-ReD 相反——文体依赖的直接证据；词表规则 AUROC 0.476（问答文体上学术词表失效，profile 分治的实证）
- **长度分档校准**（T4.3，paper+news 双域）：真人 CV p50 短/中/长 = 0.467/0.494/0.520，D-UNIF 三档阈值 0.30/0.33/0.37；数据 `_qa/length-tiers.md`
- **公文首轮校准**（T4.2，真人公开公文 15 篇 vs 构造 AI 样本 4 篇）：首轮误报 100%，三处设计修正（O-STK 转 lexicon / D-NGRAM 删除 / min_sentences 保护）后**误报 0/15 = 0%**（验收 <20% PASS）；AI 样本 7 处命中逐条人工核对成立
- **fixture 冒烟**：AI 样本 20 处命中（高 4）vs 人类样本 0 高 0 中（tests/data/）
- **全面审计一轮**（v0.6.1，2026-09-20）：pyflakes 清零；修复切分器单引号 bug（ASCII 撇号翻转引号深度吞句号，Python+JS 同步，新增回归用例）；删除死代码（Sentence.start/end 死字段、offset 死变量）；恢复 evaluate_official --show；性能基准 mattr 2 万 token 88ms，无瓶颈
- **全面审计二轮**（v0.6.2，2026-09-20）：清理 YAML 折叠说明里中文间的折叠空格（加载时统一清洗，三端生效）；四端渲染对同一规则只解释一次；修复 evaluate.py 硬编码 academic 导致 --profile general 逐规则区分度恒 0；修复 JS 破折号计数与 Python 在"———"连跑上的漂移（一致性语料补探针）；CLI 目录输入与不可读文件干净报错；压制 jieba 启动日志；网页空文本不再显示假"全清"、移动端 header 修复；移除扩展 nonce 死参数；同步 v0.6.1 切分修复后未跟进的全部校准数字
- **打磨一轮**（v0.9.0，2026-09-20）：内核——MATTR 滚动窗口 O(n·w)→O(n)（10 万 token 96ms→22ms，逐位等价有单测钉住，Python+JS 同构）；两端规则正则按引用缓存（网页逐键分析不再重复 new RegExp）；改写器 R1 数字判据显式列全角 ０-９（JS \d 不认全角，中文文案常见，回归确认口味召回不退）。表层——网页暗色模式（prefers-color-scheme 全套变量）、报告一键复制 Markdown（带 execCommand 兜底）、改写建议按删/改/留过滤、命中词在原句里 <mark> 高亮（索引区间切原文再转义，杜绝标签撞词）、原句不再截 66 字、弱命中三端统一只列前 12 处（JSON 事实源不截断）、长 URL 500+ 字符无断行串零溢出（overflow-wrap）、>6 万字先出"分析中"再算、>3 万字防抖 300→800ms、扩展报告改 --vscode-* 主题变量（暗色主题适配）。扩展——报告/改写两条命令都会把命中句按严重级画波浪线到正文（locateFindings 纯函数 node 冒烟直测，装饰失败静默降级）；CLI check/stats 支持 stdin 管道。浏览器实测：10 万字分析 233ms、全交互零 console 报错
- **综合评分轮**（v0.10.0，2026-09-20）：回应用户"要综合判断，不要碰词就判"。先做四臂消融定方向（tools/fit_score.py）：纯扣词密度 AUROC 学术 0.847 / 问答 **0.577（≈瞎猜）**，共现门控 0.810/0.496（门控是逐句指控的纪律，文档级聚合丢幅度反而降区分度），纯统计 0.965/0.828，综合（逻辑回归）**0.984/0.834，分层留出 0.974/0.868**。落地：系数进 academic/general YAML 的 scoring 段（校准只改数据），引擎出 0-100"AI 味指数"（规则特征用未门控加权密度；TTR 用字级 2-gram 评分专用口径——jieba 词级数值浏览器不可复现，评分必须两端同分）；报告首行指数+各特征贡献构成（分数可拆解，不许当黑盒），分档锚定校准语料真人 p50/p90；official 无真人配对语料不出分（宁缺毋滥），personal 是改写层不出分；短文本 <8 句不出分（与统计判定同门槛）。两端一致性含 score 逐字段对比（100 项全绿）
- **报告减负一轮**（v0.9.1，2026-09-20）：用户实测反馈"冗余说明多、不知道看哪"。三处减法：短文本（<8 句，与统计判定 min_sentences 同口径）只展示规模一行——一两句话里 CV 全是"—"、TTR 恒为 1，展示即噪音；删掉统计行里每次都出现的"（人类基线 ≈0.45，越低越平）"括号注释；"孤立弱命中"（引擎术语）改为"弱命中"。三端同步，主判定（发现 N 处）回归视觉主角
- **测试轮**（v0.11.3，2026-09-20）：以测试员视角做对抗性输入双端对拍（48 探针：引号配对/表格连竖线/emoji 与扩展区汉字/未闭合围栏/洪水字符/长句等），抓到并修复三类真 bug，判定语义零变化。**① 码点口径**：JS `.length` 数 UTF-16 码元、Python `len` 数码点——emoji/扩展区汉字上 n_chars、句长、独句段阈值/TTR 全部漂移（😀 一个算 2 vs 算 1）；JS 侧 cpLength/Array.from 全部改为码点口径。**② 空文本 avg_sentence_len**：Python 曾给 0.0、JS 给 NaN（该项一直被一致性检查豁免，掩盖了漂移），统一为 NaN 并纳入对比。**③ 正则灾难性回溯**：未闭合星号+4 万字分析 51.4 秒——EMPH 的无界 `[^*]*?` 懒惰匹配 O(n²)；EMAIL 更隐蔽，Python `\w` 认 CJK，`[\w.+-]+@` 在 4 万字长 CJK 串上 12.7 秒（JS `\w` 只认 ASCII，同一正则两端行为本就不同）。修法：EMPH 内容上限 49+CJK+49、EMAIL 改显式 ASCII 类 + RFC 5321 上限（本地部 64/域标签 63）、LINK/IMG 内容加 300/500 上限——修复后全部 ≤0.11s（470×）。副产物：CJK"伪邮箱"（长@长.cn）不再被误剥。CLI 健壮性：`-o` 指向不存在目录、规则库 YAML 改坏时从裸 traceback 改为干净报错。网页竞态：大文本双 rAF 窗口内改字/清空不再被过期任务覆盖；切模式先撤挂着的防抖；复制按钮连点不再互相抹状态。对抗探针固化进一致性检查（100→136 项，avg_sentence_len 不再豁免）。验收：88 测试 / 136 一致性 / 26 冒烟全绿，48 探针对拍零漂移，口味回归 PASS
- **文案减负轮**（v0.11.2，2026-09-20）：按"能不说明就不说明"清理全部用户可见文案，判定与数据零变化。删除的说明性文案：免责从"风格提示，不是 AI 判定；单条命中不构成证据。"减为"风格提示，不是 AI 判定。"（立场保留，说教删除）；改写页脚减为"重要数据和结论要保留；梗得人来补。"；弱命中行去掉"仅供参考"；指数 tooltip 从方法论长句（含 AUROC）减为"风格综合分，不是 AI 概率（真人 p50≈… / p90≈…）"，未校准行 tooltip 整个删除（行文案已自解释，score_note 去掉"宁缺毋滥"）；输入框占位符去掉切分方法论说明；空发现统一为"未发现模板化写作"；复制按钮删与按钮文字重复的 tooltip；场景按钮 tooltip 去掉 id 前缀；扩展 toast/状态栏同步。目录清理：删除 _qa 一次性实验脚本与走查残留，vscode-preview.html 转为 gitignore 的可再生产物，.gitignore 分组整理。验收：84 测试 / 100 一致性 / 26 冒烟全绿，口味回归 PASS，防泄漏干净，视觉验收两视图 pass
- **清理轮**（v0.11.1，2026-09-20）：全系统死代码与冗余清理，功能零变化（84 测试/100 一致性全绿+视觉零变化验收）。**修一个真 bug**：extension.js 的 activate() 引用了未 require 的 vscode（v0.9.0 延迟 require 改造时漏掉），扩展自该版本起激活即 ReferenceError、两个命令都注册不上——冒烟测试只覆盖纯函数没抓到，现补 vscode 桩回归测试（Module._load 拦截）。**复用性**：新建 web/render.js 共享渲染层（esc/fmt/hiSentence/评分行/弱命中块/共用常量），网页模板与扩展各自删掉平行实现（extension.js 瘦 ~90 行）；segment.py 抽 _text_blocks（strip_markdown 与 split_document 共用同一块组装，删 ~35 行重复）；engine.py 抽 _finding()（3 处 10 字段构造收敛）；cli.py 抽 _emit()。**简洁性/性能**：engine.py load_rules 加 lru_cache（与 JS 端 WeakMap 缓存同策略，批量评测/长循环不再重复编译正则）；engine.js/rewrite.js 导出面裁到实际使用（analyze/rewriteText），删除零引用的 splitParagraphs/stripMarkdown（Python 侧 split_paragraphs 同删）。**健壮性副产物**：build_web 的内联转义从全量 "</"→"<\\/" 收窄为仅 "</script"——前者会把 render.js esc() 里的正则 /</g 打碎（首测浏览器控制台实录），HTML5 里只有 "</script" 能提前终结脚本块
- **口径统一轮**（v0.11.0，2026-09-20）：自我实测发现两处毛边——CLI 指数带两位小数（假精度，网页端是整数），同一文本在 CLI 与网页的"TTR"数字不同（jieba 词级 vs 字级 2-gram 同名不同数）。内核：**jieba 退场**，字级 2-gram 从"评分专用口径"升格为全文唯一切分口径（统计行、评分、双端一致性对比共用；装没装任何分词库数字都一样，一致性检查不再豁免 ttr），顺带砍掉 CLI 每次启动的分词库加载；TTR 单独区分度如实重标（HC3 391 篇：0.684，词级口径旧值 0.808 不再可复现故删除）。**general 评分类平衡**：HC3 真人占比仅 24%，不加权的截距把人味文本普遍推高（统计平均的读书心得拿 74/100）；按类别倒数加权重拟合，区分度不降反微升（0.834→0.838，留出 0.868→0.870），真人 p50/p90 从 60/88 回落到 27/69；academic 系数不动（0.984 已饱和），其短文分数摆放问题与长度分层拟合记入已知限制排队。表层：够 8 句却无分的档位（公文/个人口味）三端统一给一行"未校准"说明（engine.score_note，双端一致纳入对比），指数三端统一整数显示。测试 84 项；一致性 100 项（含 score_note）；扩展冒烟 26 项

## 7. 已知限制

- 摘要级短文本：统计指标样本不足时静默不判（不报"数据不足"是设计——报告里 `—` 已说明）
- 公文体/新闻体：天然工整，句长 CV 低是真人文风，现阈值会误伤——分档阈值在 P2
- 词表特征随模型漂移：英文侧 delve（GPT-5 后骤降）、破折号（GPT-5.1 压制）已证明静态词表会过期；era 字段与季度重挖在 P3
- C-ReD 摘要语料测不到"首先…其次"等展开型套路（摘要太短），这些规则的区分度数字待完整论文语料补充
- 评分的短文摆放：全文统计在几百字级别趋饱和（2-gram TTR≈0.95），academic 档个别短真人样本会落到高档——与 doc 阈值同源的按长度分档拟合在 P2（general 已用类平衡矫正先验，academic 系数待 C-ReD 全量重抽后一并处理）

## 8. 开源边界（永不混流）

入库：代码、规则库 YAML、文档、评测脚本与评测结果（_qa/*.md|json）、测试 fixture（自写样本）。
不入库：下载的第三方语料（_qa/corpus/，版权与体积）、用户的论文与报告、API key 与本地配置。
